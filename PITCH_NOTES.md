# Заметки для питча — Башкирская языковая школа

Материалы для выступления команды, не часть пользовательского интерфейса.

## Что уже реализовано

Telegram-бот выдаёт задание, фиксирует подтверждение или исправление, начисляет очки и ведёт серию. PostgreSQL сопоставляет допустимые голоса с учётом накопленной надёжности участников. При достижении минимального числа голосов и порога веса сохраняется читаемый итоговый перевод; спорные случаи попадают в очередь экспертов. Веб показывает рейтинги, переводы, отчёт класса и экспертные решения. Переводы доступны через REST API и выгружаются в CSV/JSON. Демо-тексты **не проверены носителем языка**.

## Проверка перед презентацией — 15 пунктов

1. Сохранить резервную копию базы и выполнить `20261113_stage3_hardening.sql` в SQL Editor.
2. Проверить, что повторное применение миграции не меняет пользовательские записи (после резервной копии).
3. Запустить `python -m unittest discover -s tests -v`.
4. Запустить `python scripts/check_contract.py`.
5. Выпустить отдельный секрет эксперта через `scripts/setup_access.py --kind expert`.
6. Выпустить код приглашения преподавателя через `scripts/setup_access.py --kind teacher-invite`.
7. Запустить `scripts/smoke_test.py --expert-code "КОД"` и проверить полный PASS и очистку.
8. Запустить `scripts/check_rls.py`, убедиться, что anon не видит таблицы пользователей.
9. Запустить бота: `python -m bot.main` и проверить меню команд.
10. Зарегистрировать ученика: никнейм, короткий код класса и языковая пара.
11. Показать задание `/task`; проверить быстрое нажатие, «Верно», «Исправить» и повторный ответ.
12. Достичь пяти ответов; посмотреть прогресс и серию в `/me`.
13. Зарегистрировать преподавателя по `teacher_code`; открыть `/report` и выгрузить CSV.
14. На сайте проверить рейтинги, статус перевода, экспорт CSV/JSON, отчёт и очередь эксперта.
15. Сравнить читаемый перевод, `confirmed` (число участников) и `status` в `translations_export` и REST.

## Десять вопросов жюри

**1. Как учитываются синонимы?** Нормализация объединяет некоторые записи, `synonym_map` хранит вручную заданные эквивалентности. Семантической модели нет; похожее написание лишь помечается для эксперта.

**2. Кто гарантирует верность перевода?** На этом этапе никто: консенсус пользователей не равен филологической экспертизе. Эксперт может подтвердить итоговый вариант, но УФИЦ РАН к проекту не подключён.

**3. Можно ли накрутить баллы?** Есть минимальное время задания, интервал ответов, дневной потолок, один ответ на перевод и вес надёжности. Сговор нескольких аккаунтов всё ещё возможен.

**4. Почему два интерфейса?** Telegram удобен для коротких заданий; сайт — для анализа, отчётов, экспорта и экспертной очереди.

**5. Что храните о школьниках?** В боте хранится Telegram ID и служебные настройки; публичный рейтинг содержит только никнейм. `/delete_me` обезличивает профиль, сохраняя анонимные голоса.

**6. Как подключить новую школу?** Класс можно создать подтверждённому преподавателю по приглашению через `/newclass` или серверным скриптом. Полноценной административной панели школ пока нет.

**7. Как соблюдается авторское право?** Импорт записывает источник, лицензию и URL. Команда должна проверить разрешение и условия атрибуции CC BY 4.0; система не делает это автоматически.

**8. Почему веса не равны?** Участник, ранее распознавший подставные ошибки, получает немного больший вес; подтвердивший ошибки — меньший. Ограничение 0.5–1.5 не заменяет проверку реальными экспертами.

**9. Где аудио?** В схеме есть тип источника и время начала/конца; воспроизведения и TTS нет.

**10. Может ли другая школа подключиться по API?** Есть публичные представления и отдельный API по партнёрскому ключу для чтения и внешних предложений. Внешние предложения хранятся отдельно от голосов учеников, поэтому сами по себе не меняют консенсус.

## Честные ограничения

Не проверены носителями демо-переводы; синонимы ограничены словарём и правилами; нет TTS/проигрывания аудио и автоматической проверки лицензий; экспертный секрет общий; скоординированная накрутка остаётся возможной; сайт не выполняет ежедневные задания. Для защиты нужна **успешная реальная** проверка на Supabase, а не только локальные unit-тесты.
