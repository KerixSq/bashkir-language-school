# Башкирская языковая школа — браузер прежде всего

## Docker Compose (локальный запуск Windows 11)

Для сайта, PostgreSQL, PostgREST и анонимной авторизации предусмотрен
`docker-compose.yml`; Telegram-бот запускается отдельно по профилю `bot`.

```powershell
python .\scripts\create_docker_env.py
docker compose --env-file .env.docker up -d --build
```

Открой `http://127.0.0.1:54321/web/`. Настрой публичный ключ
`ANON_KEY` из `.env.docker` в настройках сайта. Для бота заполни
`TELEGRAM_BOT_TOKEN` в `.env.docker` и выполни
`docker compose --env-file .env.docker --profile bot up -d --build`.

**Важно:** SQL-файлы запускаются автоматически только при первом
создании пустого тома PostgreSQL. Не используй `docker compose down -v`
для обычной остановки: он удаляет базу. Подробности —
[`docs/DOCKER_WINDOWS.md`](docs/DOCKER_WINDOWS.md).

**Основной продукт — сайт.** Ученик проходит задания, подтверждает и исправляет переводы,
получает очки, смотрит рейтинги и помогает открывать главы Библиотеки Акбузата прямо
в браузере. Telegram-бот остаётся альтернативным каналом.

- **Игровые задания сообщества:** серверные очки, согласование, достижения, рейтинги; нужна локальная/доступная сеть Supabase.
- **Тренировочная тропа:** четыре типа упражнений по JSONL-колоде, XP этого устройства без регистрации; не участвует в общем консенсусе.
- **Вход ученика:** только никнейм и языковая пара. Supabase Auth Anonymous Sign-In хранит сессию в браузере; после очистки данных браузера профиль без привязанного логина восстановить нельзя.
- **Стек сайта:** один `web/index.html`, Tailwind Play CDN, Nunito + Manrope, Font Awesome 6, GSAP/ScrollTrigger, Lenis, Supabase JS через CDN. При отсутствии интернета эффекты CDN могут не загрузиться; базовые стили и тренировочная колода остаются.
- **Приватность:** браузер получает только публичный ключ. Все изменения официальных очков происходят через RPC с `auth.uid()`, без передачи идентификатора пользователя из браузера.

**Запуск / обновление:**
1. Сделай резервную копию существующей базы и останови бота.
2. Запусти локальный Supabase через `scripts/setup_local.ps1` (скрипт включает анонимный вход в `supabase/config.toml`). Если база уже запущена, перезапусти Supabase после изменения настройки Auth.
3. В существующей базе после предыдущих миграций выполни только `sql/migrations/20261113_stage8_browser_first.sql` в SQL Editor. Для чистой базы — `schema.sql` → `seed.sql` → `logic.sql`.
4. Проверь наличие импортированных `fragment_pairs` для `ba-ru` и/или `ba-kk`. При пустой базе сначала импортируй корпус.
5. Запусти сайт: `python -m http.server 8000 --bind 127.0.0.1`, открой `http://127.0.0.1:8000/web/`.
6. В «Настройках сайта» укажи `http://127.0.0.1:54321` и только публичный ключ из `npx supabase status` (или заранее впиши эти **публичные** значения в `web/index.html`).
7. Введи никнейм, выбери пару, получи фразу и проверь перевод. Рейтинг обновляется после ответа.

**На телефонах:** `127.0.0.1` означает сам телефон, а не твой ноутбук. Для показа на другом устройстве нужно отдельно настроить безопасный сетевой доступ к API и HTTPS. Не открывай наружу dev-стек Supabase CLI.

Основной канал — сайт. Ученик начинает с никнейма, получает задания и проверяет предложенные переводы прямо в браузере. PostgreSQL согласует ответы и начисляет очки. Рейтинги, переводы, отчёты классов и очередь экспертов доступны здесь же. Telegram-бот сохраняется как альтернативный канал участия.

**Это хакатонная сборка.** Есть веб-игра с учебными упражнениями, но без единого аккаунта с ботом; нет озвучки и семантического ИИ. Синонимы сопоставляются только нормализацией и явно заданным словарём. Работа в реальном Supabase требует отдельной интеграционной проверки.


## Для учеников

На сайте есть **игра-приключение без регистрации**: карта из трёх этапов, уроки по пять фраз, выбор перевода, проверка ошибочного варианта, сбор предложения из слов и ввод ответа. Верные ответы, повторение ошибок, XP, серия дней и награды сохраняются **в браузере**. Это тренировочные очки, они не влияют на рейтинг школы и не записываются в PostgreSQL. Для общего рейтинга и проверки переводов есть отдельный режим заданий сообщества **на сайте**. Его очки, уровни и серии хранятся на сервере; те же SQL-правила использует Telegram-бот. После ответа бот предлагает «Следующее задание».

Чтобы на опубликованной странице работала кнопка **«Начать в Telegram»**, укажи публичное имя бота без `@` в константе `PUBLISHED_BOT_USERNAME` внутри `web/index.html`. Если имя не задано, кнопка **«Telegram-бот»** ведёт к инструкции, а не по несуществующей ссылке. Для публикации также нужно настроить `PUBLISHED_SUPABASE_URL` и `PUBLISHED_PUBLIC_KEY` — только публичные значения.

Визуальный стиль сайта — мультяшное приключение с Акбузатом. Главная страница устроена как языковой тренажёр: навигация сбоку или снизу на телефоне, извилистая тропа из **действующих** уроков, ежедневная цель и отдельный экран занятия. Шесть точек ведут к трём учебным этапам; дополнительная точка повторяет практику существующего этапа. Графика своя, без заимствования персонажей и фирменных элементов других приложений. Иллюстрации хранятся в `web/assets/`, без CDN. Игровые награды выдаются только за выполненные задания. Подробнее: [`docs/APP_DESIGN.md`](docs/APP_DESIGN.md) и [`docs/VISUAL_DESIGN.md`](docs/VISUAL_DESIGN.md).

План проверки спроса, вопросы ученикам и критерии пилота: [`docs/STUDENT_RESEARCH.md`](docs/STUDENT_RESEARCH.md). Это исследовательские гипотезы, а не подтверждённая заинтересованность аудитории.

## Как устроено

```text
JSONL БГПУ / текстовые файлы
          ├─→ Python-экспорт → веб-колода → личная практика в браузере
          ↓
      Python-импорт → PostgreSQL (Supabase)
                            ↑
                Telegram-бот: ответы
                            ↓
                 SQL: голоса, очки, консенсус
                            ↓
                веб-страница + REST API
```

- `sql/` — таблицы, логика PostgreSQL и история миграций.
- `bot/` — FSM-регистрация, задания, рейтинги, профиль и отчёты.
- `web/index.html` — статичная игра и интерфейсы отчётности без сборки.
- `scripts/` — импорт, проверка, подготовка демо-данных.
- `tests/` — изолированные Python-тесты.
- `API.md` — описание публичных, серверных и партнёрских методов.
- `PITCH_NOTES.md` — сценарий показа и ответы жюри.

## Главное нововведение: общая библиотека Акбузата

Помимо личной веб-игры есть **кооперативная библиотека**, которая растёт только от настоящих подтверждённых переводов в PostgreSQL. Счётчик `adventure_progress` показывает подтверждённые переводы выбранной языковой пары и количество спорных фрагментов. Источники с лицензией `demo` не учитываются; веб-XP не участвуют в голосовании. Главы библиотеки открываются на **1, 5 и 15** подтверждённых переводах. Кнопка «Обновить прогресс» делает один запрос через публичный REST API; без подключения интерфейс честно показывает, что данные недоступны.

**Полностью локальный запуск:** если не хочешь использовать облачную базу, смотри [`docs/LOCAL_WINDOWS.md`](docs/LOCAL_WINDOWS.md). В нём подготовлен `scripts/setup_local.ps1` для Docker Desktop и локального Supabase CLI; сайт и бот также запускаются на ноутбуке. Локальная среда не предназначена для выставления в интернет.

**Важно для существующей базы:** после stage5 последовательно примени `sql/migrations/20261113_stage6_expedition.sql` и `sql/migrations/20261113_stage7_runtime_fixes.sql`. Если stage6 уже применена, запусти только stage7. Для новой базы достаточно `schema.sql`, `seed.sql`, `logic.sql`: все исправления уже входят в `logic.sql`. Не выполняй старые миграции поверх чистой установки.

## Запуск на Windows 11

Нужны Python 3.11+, аккаунт Supabase (Free) **или локальная среда по инструкции выше**, токен бота от [@BotFather](https://t.me/BotFather). Работай из корневой папки проекта в PowerShell.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r bot\requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
```

В `.env` заполни (или автоматически обнови локальные ключи через `scripts/setup_local.ps1`):

| Переменная | Значение |
|---|---|
| `SUPABASE_URL` | Supabase → Connect → Project URL |
| `SUPABASE_SECRET_KEY` | Server secret key или legacy service_role — **только сервер** |
| `SUPABASE_PUBLIC_KEY` | Publishable key или legacy anon — для сайта и RLS-теста |
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather |

Не публикуй `.env` и не вставляй секретный ключ в браузер.

**Быстрый локальный запуск:** `scripts/setup_local.ps1` автоматически сохранит локальные ключи в `.env`, не затронув токен Telegram, и создаст резервную копию старых настроек. Затем выполни `python scripts/doctor.py`; после проверки запусти сайт и бота одной командой `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_local.ps1`. Старые облачные настройки при необходимости лежат в `.env.backup-*` (не коммить!). Подробности — в [`docs/LOCAL_WINDOWS.md`](docs/LOCAL_WINDOWS.md).

**Для новой пустой базы:** в Supabase → SQL Editor по порядку выполни `sql/schema.sql`, `sql/seed.sql`, `sql/logic.sql`. Миграции для старой версии отдельно не запускай.

**Для существующей базы:** если stage1–stage4 уже выполнены, последовательно запускай stage5 → stage6 → stage7. Пропускай только те этапы, которые уже точно применены; старые файлы `schema/seed/logic` повторно не запускай. Stage7 устраняет гонку при переходе бота в режим исправления. Миграция идемпотентна.

Проверь проект:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts\check_contract.py
.\.venv\Scripts\python.exe scripts\check_rls.py
.\.venv\Scripts\python.exe scripts\demo_readiness.py
.\.venv\Scripts\python.exe scripts\setup_access.py --kind expert
.\.venv\Scripts\python.exe scripts\smoke_test.py --expert-code "ТВОЙ_СЕКРЕТ_ЭКСПЕРТА"
```

`demo_readiness.py` делает read-only запросы, показывает количество активных фраз, ответов и подтверждений, но не создаёт искусственных голосов. `check_contract.py` **только читает код** и не проверяет выполнение SQL. `check_rls.py` и `smoke_test.py` обращаются к твоему Supabase: они должны завершиться без `FAIL` перед показом. `smoke_test.py` создаёт и очищает технические данные. Если очистка сообщит об ошибке, проверь временные строки вручную.

Запусти бота:

```powershell
.\.venv\Scripts\python.exe -m bot.main
```

В отдельном терминале подними сайт:

```powershell
python -m http.server 8000
```

Открой `http://localhost:8000/web/`. Для самостоятельной игры достаточно сгенерировать колоду из JSONL (см. ниже). Для рейтингов и проверенных переводов подключи URL проекта и **публичный** ключ Supabase. Для публикации статичной страницы подойдёт GitHub Pages; бот с long polling должен оставаться запущенным отдельно.

## Корпус и лицензия

Источник: [bashkorttele/trilingual-parallel-phrasebooks-bgpu](https://huggingface.co/datasets/bashkorttele/trilingual-parallel-phrasebooks-bgpu), разговорники БГПУ, опубликованные Фондом сохранения и развития башкирского языка. Лицензия текстов — [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). Атрибуция обязательна.

- **Правообладатель:** ФГБОУ ВО «БГПУ им. М. Акмуллы» (согласно `data/phrasebooks/NOTICE`).
- **Издатель:** АНО «Фонд сохранения и развития башкирского языка» (согласно `data/phrasebooks/NOTICE`).
- **Изменения:** дедупликация фраз, выбор наиболее частого русского варианта, отбор языковых пар `ba-ru` и `ba-kk`, добавление учебных ошибочных вариантов по формальным правилам.
- CC BY 4.0 для текстов корпуса не означает разрешения на использование иллюстраций и оформления печатных изданий.

Авторы датасета предупреждают: тройки переводов **не проверены построчно**. Статус `collecting` после импорта не означает подтверждение носителем языка. Ошибочные учебные варианты выбираются из других фраз похожей длины и требуют ручной проверки.

В этом архиве пять исходных JSONL уже находятся в `data\phrasebooks\` вместе с `LICENSE` и `NOTICE`; их SHA-256 совпадает с зафиксированной ревизией в `docs/CORPUS_PROVENANCE.json`. Если потребуется скачать их заново, используй `scripts/download_phrasebooks.py`. Перед публикацией данных проверь условия лицензии и атрибуции. В текущем архиве находятся пять JSONL и файлы `LICENSE`/`NOTICE` в `data/phrasebooks/`; перед публичной публикацией проверь условия их распространения и атрибуцию.

```powershell
.\.venv\Scripts\python.exe scripts\import_phrasebooks.py --dir .\data\phrasebooks --bad-share 0.2 --seed 42
```

### Игровая колода для сайта

В этом архиве уже включена **полная локальная игровая колода на 700 фраз** (350 `ba-ru` и 350 `ba-kk`) из опубликованного корпуса БГПУ. Для трёх игровых этапов **ничего скачивать дополнительно не требуется**. Чтобы создать новую колоду с другим набором фраз, используй команду (ключи Supabase не нужны):

```powershell
.\.venv\Scripts\python.exe scripts\export_learning_deck.py --dir .\data\phrasebooks --per-pair 350 --seed 42
python -m http.server 8000
```

Открой `http://localhost:8000/web/` → «Играть на сайте». Скрипт создаст `web/assets/learning-deck.json`, который можно публиковать вместе со статичным сайтом (включая GitHub Pages). Колода содержит только тексты и переводы из скачанного корпуса; синтетических предложений и персональных данных в ней нет. Перед публикацией проверь лицензию и выборку соответствий. Если колоды нет, можно загрузить JSON-файл в игровом разделе или подключить публичный Supabase с подтверждёнными переводами. Дополнительная инструкция: [`docs/GAMEPLAY.md`](docs/GAMEPLAY.md).

**Отличие двух режимов в браузере:** «Главное приключение» сохраняет реальные голоса, очки и прогресс на сервере. Отдельная тренировочная тропа запоминает упражнения локально, не начисляет официальные очки и не участвует в консенсусе.

Импортёр сохраняет исходные ID в `phrasebook_rows` в формате `имя-файла::id`, пропускает дубли и не перезаписывает существующие ответы. Повторный запуск должен сообщить о нуле новых фрагментов. Поддерживаются **только** `ba-ru` и `ba-kk`. При несовпадении данных уже известной строки импорт останавливается вместо молчаливой перезаписи.

**Качество корпуса:** локальная проверка показала 9857 строк, 9852 подходящих, 3834 уникальных фрагмента, 5208 языковых связей и 1206 групп с конкурирующими русскими переводами. Это не значит, что 5208 переводов уже подтверждены носителями. Подробности — в [`docs/CORPUS_AUDIT.md`](docs/CORPUS_AUDIT.md).

**Перед первым импортом проверь качество без подключения к Supabase:**

```powershell
.\.venv\Scripts\python.exe scripts\import_phrasebooks.py --dir .\data\phrasebooks --bad-share 0.2 --seed 42 --dry-run --review-out .\data\phrasebook-review.csv
```

CSV показывает исходные и учебные ошибочные варианты. Проверь все подставные варианты и спорные совпадения на короткой выборке с носителем языка. Проверка только по похожей длине **не гарантирует** правдоподобность ошибки. Нормализация при дедупликации может объединить вопрос и утверждение: импортёр выводит количество таких групп. Если они есть, их нужно проверить отдельно.


Для своего `.txt` или `.md` используй `scripts/import_text.py`, затем `scripts/export_for_translation.py` и `scripts/import_translations.py`. Команды и требования к лицензии — в `scripts/IMPORT_GUIDE.md`, формат CSV и запрос к переводчику — в `PROMPT_TRANSLATION.md`. Не публикуй материалы без проверки прав.

## Классы и демонстрация

```powershell
.\.venv\Scripts\python.exe scripts\seed_demo.py
```

Команда создаёт **3 демо-школы, 6 классов и 15 вымышленных участников**, распечатывает коды классов, **но не подделывает переводы или голоса**. Поэтому с пустой базой рейтинги будут пустыми. Сначала загрузи корпус и заранее собери реальные ответы участников на одну фразу. Новые задания сначала направляются к фрагментам с уже собранными голосами, чтобы достигать консенсуса. Выбор при равенстве остаётся случайным — перед демонстрацией проверь выбранные фразы и подготовь резервный пример.

Флаг `--with-demo-texts` включает старые синтетические примеры, **не проверенные носителем** (`license='demo'`). Для показа с реальным корпусом не используй его. `--reset-demo` удаляет старые демо-данные **и затем вновь создаёт демо-классы и участников**; скрипт откажется удалять текст, на который ответили реальные люди.

Ученику передавай `join_code` (6–8 символов), преподавателю — отдельный секретный `teacher_code`. Подтверждённый преподаватель может создать до трёх классов через `/newclass`, но только с кодом приглашения, который создаётся командой:

```powershell
.\.venv\Scripts\python.exe scripts\setup_access.py --kind teacher-invite
```

## Команды бота

| Команда | Действие |
|---|---|
| `/start` | Регистрация: никнейм, роль, код класса, языковая пара |
| `/task` | Подтвердить, исправить или пропустить перевод |
| `/pair` | Сменить языковую пару (показываются только пары с заданиями) |
| `/cancel` | Сбросить незавершённое действие |
| `/me` | Профиль, очки, уровень, серия, бейджи |
| `/top` | Рейтинг и выбор периода |
| `/report` | Отчёт и CSV для преподавателя |
| `/newclass` | Создание класса по секретному приглашению |
| `/privacy`, `/delete_me` | Правила приватности и обезличивание профиля |
| `/help` | Справка |

**CI:** unit-тесты, контракт SQL и критические синтаксические ошибки Ruff обязательны. Полный линтинг и форматирование пока работают как отчётные проверки: исправляй их замечания перед финальным коммитом, они не считаются успешно пройденными локально без запуска Ruff.

**Что убрали для стабильности:** фоновые напоминания `/remind`, Docker-конфигурацию и отдельный скрипт пилотной сводки. Это необязательные функции, не входящие в главный сценарий хакатона. Старые настройки напоминаний в БД оставлены ради совместимости, но не используются ботом.

## Согласование и очки

| Параметр `config` | Значение | Смысл |
|---|---:|---|
| `min_votes` | 3 | Минимум ответивших для консенсуса |
| `consensus_share` | 0.6 | Доля веса лидирующего варианта |
| `expert_after_votes` | 5 | После этого без консенсуса — очередь экспертов |
| `points_per_answer` | 10 | Обычный ответ |
| `bonus_catch_error` | 15 | Исправление подставной ошибки |
| `bonus_match_consensus` | 5 | Ответ совпал с финальным вариантом |
| `daily_goal` | 5 | Цель дня |
| `daily_points_cap` | 150 | Верхний предел очков за день |
| `min_answer_seconds` | 2 | Минимум между показом и ответом |
| `level_step` | 100 | Шаг нового уровня |
| `bad_variant_probability` | 0.2 | Доля заданий с подготовленной ошибкой |

Веса зависят от предыдущих ответов участника на подставные ошибки (формула в `scripts/pure.py` и SQL). Количество участников учитывается отдельно от суммы весов. Синонимы сопоставляются только по простым правилам и `synonym_map`, а не «пониманию смысла». Подтверждение чужого ошибочного варианта не приносит очков. Отчёты и суточные границы работают по `Asia/Yekaterinburg` (Уфа, UTC+5).

## REST и приватность

- **Публично:** `translations_export`, рейтинги; на сайте видны никнеймы, но не Telegram ID.
- **По коду:** отчёт преподавателя и очередь решений экспертов.
- **По партнёрскому ключу:** `api_get_fragments`, `api_submit_answer`. Внешние ответы хранятся отдельно от ученических голосов и не влияют на консенсус. Выпуск ключа: `scripts/create_api_key.py`.
- **Только серверу:** пользователи, ответы, статистика пользователей, создание/выдача заданий и запись голосов.

Форматы, `curl`, права и примеры ошибок — в `API.md`. RLS и права выполнения RPC необходимо **проверить** через `check_rls.py` на живой базе. Views Supabase могут выполнять запросы от имени создателя, поэтому безопасность обеспечивается также явными `REVOKE/GRANT` и проверкой возвращаемых колонок.

## Известные ограничения

- Нет независимой проверки качества перевода и полной семантической оценки синонимов.
- Аудио хранится только координатами источника; воспроизведения/TTS нет.
- В браузере есть два режима: официальная проверка переводов с серверными очками и самостоятельные упражнения с локальным XP. Анонимный вход привязан к устройству; перенос на другое устройство без постоянной учётной записи пока не поддерживается.
- Экспертный доступ по одному общему коду, не персональная идентификация экспертов.
- Сговор нескольких аккаунтов невозможно полностью исключить.
- Без работающего процесса Python бот недоступен; статический сайт не заменяет бот-сервер.

**Перед защитой:** запусти `smoke_test.py` и `check_rls.py`, проверь импорт корпуса, регистрацию, три независимых ответа, подтверждение перевода, рейтинг и выдачу записи по REST. Сценарий показа — `PITCH_NOTES.md`.

## Новый игровой интерфейс: Academy UI

Переработали первый экран по мотивам учебных приложений с последовательным маршрутом: большая кнопка запуска, три настоящих этапа, отдельный экран вопроса и обратная связь после ответа. Образ Акбузата, пейзажи Урала и цветовая система — собственные. **Код и графику LinguaLearn не копировали.** Его архив использован только для сравнения структуры учебного пути и взаимодействий.

- **«Играть бесплатно»** сразу открывает доступный урок на встроенной колоде БГПУ; подключение к базе не требуется. Прогресс практики хранится локально.
- **«Проверить перевод»** открывает форму браузерного участия в общем согласовании. Ей нужен настроенный Supabase REST и анонимный вход.
- Закрытые этапы разблокируются за действительно освоенные фразы (после 8 и 20 уникальных совпадений с корпусом).
- Выбор вариантов 1–4 с клавиатуры, Enter — проверить/продолжить, Escape — выйти (с подтверждением, если урок активен).
- Кнопки экспорта и экспертных решений используют существующее серверное API. Вымышленные рейтинги отдельно маркируются «ДЕМО».

Никаких новых таблиц, зависимостей Python и SQL-миграций для обновления интерфейса не требуется. Страницу можно посмотреть командой `python -m http.server 8000` из корня проекта, затем открыть `http://127.0.0.1:8000/web/`.

Визуальная и функциональная проверка в браузере без Supabase доступна через `tests/browser_learning_path.py` (нужен локально установленный Playwright и Chromium); она не заменяет `scripts/smoke_test.py` и `scripts/check_rls.py` на настоящем PostgreSQL.
