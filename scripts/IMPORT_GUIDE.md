# Как импортировать реальный открытый текст

1. Открой [ba.wikipedia.org](https://ba.wikipedia.org/) и сам выбери статью. Проверь конкретную лицензию, ссылку на историю правок, ограничения иллюстраций и цитат. Для текста Википедии часто действует CC BY-SA 4.0, но лицензию нужно перепроверять на странице. Для атрибуции сохрани название, ссылку, автора/историю, условия лицензии и изменения.
2. Скопируй разрешённый отрывок в UTF-8 файл `article.txt` (не помещай в GitHub материалы, права которых неясны). Сам проект не подставляет башкирские тексты.
3. Выполни в PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts\import_text.py --file article.txt --title "[Название статьи]" --license "CC BY-SA 4.0" --url "https://ba.wikipedia.org/wiki/[путь]" --chapter "Введение"
```

Для `.md` с заголовками второго уровня используй `--chapter-pattern "^## (.+)$"`. Позиции сохраняются в БД; повтор того же содержимого не импортируется по SHA-256 (таблица `import_batches`). Вывод показывает число новых и пропущенных фрагментов.

4. Проверь таблицы `sources`, `fragments`, `import_batches` и координаты `chapter`, `position` через psql в контейнере db; команды подключения — [Windows setup](../docs/WINDOWS_SETUP.md). Studio/Table Editor отсутствует в основном Compose. Неполный импорт после ошибки можно запускать заново, но если упал между записью фрагментов и контрольного хеша, потребуется ручная проверка дублей.
5. Выгрузи CSV с непереведёнными фрагментами через `export_for_translation.py`. Подготовь перевод по [формату CSV](../docs/CONTENT_AND_AUDIO.md#работа-с-переводами-из-csv), проверь результат с носителем и только затем загрузи `import_translations.py`.

**CC BY-SA:** важны атрибуция, ссылка на условия лицензии и указание на изменения; к переработанному материалу могут применяться условия ShareAlike. Не надо автоматически считать любой текст на сайте свободным для коммерческого переиздания.

## Разговорники БГПУ (JSONL)

Источник: https://huggingface.co/datasets/bashkorttele/trilingual-parallel-phrasebooks-bgpu
Лицензия текстов: CC BY 4.0, https://creativecommons.org/licenses/by/4.0/.
Обязательно указать правообладателя и издателя из файла `NOTICE`. Непроверенное выравнивание троек не считается экспертной валидацией.

Сохрани все пять файлов `data-ba-ru-{alt,ar,kk,sah,zh}.jsonl` в `data/phrasebooks` и запусти из PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts\import_phrasebooks.py --dir .\data\phrasebooks --bad-share 0.2 --seed 42
```

Для базы со старыми миграциями stage1–stage4 выполни также `sql/migrations/20261113_stage5_quality.sql` — она сохраняет исходные ID с префиксом имени файла. Для новой базы достаточно `schema.sql`, `seed.sql`, `logic.sql`.
Скрипт оставляет `ba-ru` и `ba-kk`, сохранит все исходные идентификаторы в закрытой таблице `phrasebook_rows` и выведет статистику пропусков и дубликатов. Для чистого проекта миграция отдельно не нужна (таблица есть в `schema.sql`).
