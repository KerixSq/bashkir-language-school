# Инструкции Codex · Башкирская языковая школа

Работай в этом репозитории, не создавай второй проект. Стек: Python 3.11+, aiogram 3, Supabase/PostgreSQL локально (Docker Desktop), один `web/index.html` с обычным JavaScript. Данные — разговорники БГПУ, только допустимые языковые пары. Не придумывай тексты на башкирском и казахском.

## Главные правила

1. Прочитай README, docs/WINDOWS_SETUP.md и нужные исходники перед правкой. docs/LOCAL_WINDOWS.md относится только к альтернативному CLI.
2. Сначала воспроизведи ошибку. Меняй минимальное число файлов и добавляй тесты.
3. При изменении БД: новая **идемпотентная** миграция в `sql/migrations/` с транзакцией, а также обновлённые `sql/schema.sql` / `sql/logic.sql` для чистой установки.
4. Никаких секретов в Git, браузере или логах. Публичные представления не должны возвращать ID школьников.
5. Не подменяй серверные очки и общественное согласование прогрессом `localStorage`.
6. Новые кнопки должны выполнять настоящие действия; ошибки и пустые состояния должны быть честными.
7. Локальный Supabase CLI **не публикуй** в интернет. Не делай `supabase db reset`, `stop --no-backup` или удаление данных без разрешения.
8. Не ставь лишние зависимости и не добавляй платные API.
9. После каждой задачи запускай `python -m compileall -q bot scripts tests`, `python -m unittest discover -s tests -v`, `python scripts/check_contract.py`; если возможно, `ruff check .` и `ruff format --check .`.
10. На реальной базе дополнительно запускай `scripts/smoke_test.py` и `scripts/check_rls.py`. Разделяй реально пройденные проверки и ожидаемые.

## Ключевой сценарий для жюри

БГПУ JSONL → импорт в PostgreSQL → Telegram-задание → несколько независимых голосов → согласованный перевод → `translations_export` → рост счётчика `adventure_progress` на сайте → API. Проверка школьниками — не полноценная экспертиза; синонимы сопоставляются только правилами и словарём.

Отвечай на русском, файлы и идентификаторы оставляй на английском. В конце дай кратко: изменённые файлы, проверки с результатом, что запускать в PowerShell и что не подтверждено.

## Продолжение локальной разработки

- При уже применённой `stage6` обязательно проверь наличие `sql/migrations/20261113_stage7_runtime_fixes.sql`. На чистой базе эта функция уже есть в `sql/logic.sql`.
- В альтернативном CLI-режиме после `scripts/setup_local.ps1 -UseSupabaseCli` ключи появляются в активном `.env`; старый файл, если был, резервируется как `.env.backup-*`. Код Telegram-бота этот скрипт не меняет.
- Быстрая проверка локальной базы: `python scripts/doctor.py`, затем `scripts/check_rls.py` и `scripts/smoke_test.py`. При ошибке подключения не принимай это за PASS.
- Для запуска сайта и бота одной командой: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_local.ps1`.
