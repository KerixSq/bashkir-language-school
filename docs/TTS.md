# Башкирская озвучка · Silero bak_aigul

## Что доступно

В `web/assets/audio/` включены **40 настоящих синтезированных WAV** (24 kHz, mono PCM16, около 3,9 MB) и `manifest.json`. Они созданы только из включённой колоды БГПУ, без новых предложений и изменения переводов. В manifest указаны исходные ID, нормализованный текст, голос, версия модели и SHA-256 каждого файла. Одинаковые нормализованные фразы обеих языковых пар используют один файл.

Кнопка «Слушать» находится рядом с башкирской фразой в тренировке и серверной проверке. Воспроизведение начинается только по нажатию; повторное нажатие, смена задания, выход и уход со страницы останавливают звук. Есть состояния загрузки, остановки, отсутствия озвучки и ошибки с повторной попыткой. Файлы раздаются существующим Nginx или обычным статическим HTTP-сервером. SQL, Docker, начисление XP и серверные очки не изменены. На клиентские или внешние TTS-сервисы фразы не отправляются.

**Это демонстрационная синтетическая речь. Произношение не проверено носителем.** До использования озвучки в учебном пилоте необходима оценка носителем башкирского языка, включая специфические буквы и ударения. Техническое воспроизведение не подтверждает языковую правильность. Аудио покрывает 40 из 627 уникальных допустимых для генератора фраз; остальные задания работают в текстовом виде. Корпус также содержит варианты через `/`: генератор их пропускает без изменения текста. Русский браузерный голос не используется как башкирский; SpeechSynthesis не вызывается.

## Генерация на Windows

Готовые WAV уже в Git: для запуска сайта PyTorch не нужен. Для генерации создайте отдельное необязательное окружение, не используемое контейнерами:

```powershell
python -m venv .venv-tts
.\.venv-tts\Scripts\python.exe -m pip install -r requirements-tts.txt
.\.venv-tts\Scripts\python.exe scripts/generate_tts.py --limit 40 --dry-run
.\.venv-tts\Scripts\python.exe scripts/generate_tts.py --limit 40 --download-model
```

`--download-model` скачивает только официальный URL в `.cache/tts/` (не входит в Git). Без этого флага передайте уже проверенный файл через `--model-file C:\path\v5_cis_base_nostress.pt`. `--dry-run` не требует модели, сети и PyTorch, ничего не записывает. Пример расширения на всю колоду:

```powershell
.\.venv-tts\Scripts\python.exe scripts/generate_tts.py --voice bak_aigul --model-file .cache/tts/v5_cis_base_nostress.pt
```

Без `--limit` обрабатываются все допустимые уникальные фразы. `--output-dir` задаёт папку результата (по умолчанию `web/assets/audio`); для сайта содержимое должно оказаться именно там. Существующие WAV проверяются и пропускаются; хеш имени включает текст, голос, модель и контрольную сумму модели. Manifest отражает выбранный текущей командой набор. Повторная команда с теми же аргументами не пересинтезирует файлы. Повреждённый файл вызывает ошибку, а не считается успешным кешем. Зависимости TTS не добавлены в зависимости приложения.

## Как посмотреть и прослушать демо

Основной запуск приложения прежний, по README через Compose. Для статической проверки: `python -m http.server 8000`, адрес `http://127.0.0.1:8000/web/`. Пример реального файла из пакета: [«ни хәл итәһең инде!»](../web/assets/audio/003d20d41ef1b04a2ab58e4062b9833d73df337d222aba68e23a42662c64aa49.wav). Другие тексты и пути — в manifest; никакого автозвука при открытии страницы нет. Чтобы проверить весь демонстрационный набор в тренировке, можно загрузить JSON, отобрав записи основной колоды по `source_ids` manifest (так делает Playwright; языковые данные не выдумываются).

## Проверки и ограничения

Локально выполнены: 113 unit-тестов, compileall, контракт, Ruff; `browser_tts_checks.py` воспроизводит реальные WAV через Chromium на 390/1440 px, проверяет движение currentTime и декодирование, Enter, повторную остановку, смену задания, выход, 404 с повтором, отсутствие фразы и каталога, запрет небезопасных путей. Контрол серверного режима проверяется изолированно с настоящей фразой корпуса; это не имитация успешного входа. Настоящий вход и цикл ответа отдельно проверяются существующим Docker E2E в Actions. `browser_visual_checks.py` проверяет шесть размеров, а `browser_checks.py` — реальные учебные сценарии и сохранность XP. Новые TTS-тесты выполняются в CI без PyTorch, по включённым аудиофайлам.

Физический телефон/Safari и оценка носителем не проверены. Chromium headless подтверждает воспроизведение и декодирование, а не качество произношения. Скриншоты: `test-results/visual/tts-*`; в CI — артефакт `interface-screenshots`.
