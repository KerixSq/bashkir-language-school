**Дата:** 13.11.2026. Проект: финальная игровая сборка с кооперативной библиотекой Акбузата.

## Проверено в изолированном окружении

- `python -m unittest discover -s tests -v` — 62 теста успешно.
- `python -m compileall -q bot scripts tests` — успешно.
- `python scripts/check_contract.py` — успешно (проверка исходников, **не исполнение SQL**).
- `node --check` для двух inline-скриптов сайта — успешно.
- Chromium через Playwright: в тестовой странице с **подменёнными ответами API** проверен ввод локального URL `http://127.0.0.1:54321`, смена языковой пары библиотеки, пересчёт глав и отсутствие исключений JavaScript. На viewport 390 px горизонтального переполнения не было. Этот тест не использовал настоящую сеть/базу и не является подтверждением API, RLS или дизайна со всеми загруженными изображениями.
- `ruff` отсутствовал; `pip install ruff` не выполнился из-за недоступной сети. Нельзя считать линтинг пройденным.

## Не проверено исполнением

- PostgreSQL на Docker Desktop и идемпотентность миграции при повторном SQL-выполнении.
- Настоящий `smoke_test.py`, `check_rls.py`, Telegram long polling и импорт реального набора JSONL.
- Фактическая приватность RLS при запросах с настоящим публичным ключом.
- Работа с телефона при подключении к локальному API: на другом телефоне `localhost` указывает на сам телефон, а не на ноутбук.

## Три главные ручные проверки перед защитой

1. Выполни `schema.sql`, `seed.sql`, `logic.sql` на **чистой локальной** базе и запусти `smoke_test.py` с созданным экспертным кодом. Не запускай миграции на чистой базе повторно.
2. Запусти `check_rls.py` с публичным ключом, проверь закрытые таблицы и новый view `adventure_progress`.
3. Импортируй настоящий БГПУ JSONL, получи голосами нескольких участников хотя бы один `confirmed` перевод, затем нажми «Обновить прогресс» — значение должно увеличиться на 1. Личные XP веб-игры не должны его менять.

Сборка не заявляется полностью проверенной на живых данных до выполнения этих действий.
