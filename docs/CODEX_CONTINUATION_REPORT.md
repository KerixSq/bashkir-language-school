# Продолжение после исчерпания лимита Codex

База: пользовательский архив `Архив ZIP - WinRAR.zip`. Старые исходники сохранены, новая копия проекта предоставляется **без** `.git`, `.ruff_cache`, `.env`, `__pycache__` и других локальных служебных файлов.

## Изменения

- `scripts/setup_local.ps1`: исправлена ситуация, когда при существующем `.env` локальные ключи записывались в `.env.local.generated`, который бот не читает. Теперь используется `scripts/configure_local_env.py`, сохраняющий текущий токен Telegram и резервную копию старого `.env`.
- `scripts/configure_local_env.py`: проверка, что URL локальный; поддержка новых `PUBLISHABLE_KEY`/`SECRET_KEY` и прежних `ANON_KEY`/`SERVICE_ROLE_KEY`; безопасное обновление значений без вывода секретов.
- `scripts/doctor.py`: read-only проверка подключения к локальному REST, структуры публичного представления `adventure_progress` и запрета доступа к `users`. Сетевые ошибки не принимаются за успешный запрет. Режим `--require-bot` нужен для запуска бота, `--offline` проверяет файлы без сети.
- `scripts/run_local.ps1`: сайт и бот запускаются одной командой; перед запуском проверяются настройки и доступ к базе. При завершении бота локальный веб-сервер останавливается.
- `tests/test_local_setup.py`: регрессии для изменения `.env`, проверки локальности, ошибок сети и приватности. В `tests/browser_checks.py` и `tests/browser_api_checks.py` добавлена опциональная переменная `BROWSER_EXECUTABLE` для системного браузера.
- `scripts/check_contract.py`: добавлена проверка stage7 и новых скриптов.
- `README.md`, `docs/LOCAL_WINDOWS.md`, `API.md`, `docs/RELEASE_CHECKLIST.md`, `AGENTS.md`: обновлены миграции, команды запуска, атрибуция и объём поставляемых данных.
- `docs/CORPUS_AUDIT.md`: зафиксирована реальная статистика пользовательских JSONL и SHA-256 сверка с манифестом.
- `START_HERE.md`: короткий и безопасный маршрут запуска с нуля.

## Критический чеклист перед защитой

1. На ноутбуке сделать копию данных; не сбрасывать существующую БД.
2. Если база существующая, проверить что `stage7_runtime_fixes.sql` уже применена; если новая — выполнить schema → seed → logic.
3. Запустить `scripts/doctor.py --require-bot` с локальным API; результат должен быть PASS для публичного view и запрета чтения `users`.
4. Выполнить `scripts/check_rls.py` и `scripts/smoke_test.py` с настоящим серверным ключом на локальном PostgreSQL.
5. Проверить реальный импорт JSONL, отсутствие дублей и содержимое `translations_export`.
6. Провести три независимых голоса, убедиться, что меняется `adventure_progress` и сайт отображает новый счётчик.
7. Пройти в Chromium/Edge всю веб-игру на телефоне и компьютере; проверить RLS из другого браузера и отсутствие секретов в HTML.
8. Запустить `ruff check .` и `ruff format --check .`, исправить замечания.
9. Сверить атрибуцию с `data/phrasebooks/NOTICE` и проверить выборку реальных переводов носителем.
10. Проверить сохранение данных при штатном перезапуске ноутбука и Docker Desktop.

## Ограничения продукта, которые важно честно назвать

Личные XP веб-игры находятся в localStorage и не входят в очки Telegram. Корпус предварительный и не прошёл сплошную экспертную проверку. Синонимы учитываются только простыми правилами и словарём; TTS нет. Локальный API нельзя выставлять в интернет напрямую. Успех unit-тестов не подтверждает работу Docker и PostgreSQL.
