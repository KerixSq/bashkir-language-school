## Доказательства

- Видео: `test-results/checkpoint/chromium-mobile.webm`, `test-results/checkpoint/webkit-mobile.webm`.
- Скриншоты: `test-results/checkpoint/{chromium,webkit}-{audio,finish,profile}.png`.
- Журнал мобильных прогонов: `test-results/checkpoint/results.json` (включает ожидаемые сетевые отказы).
- Шесть размеров: `test-results/visual/`; остальные сценарии: `test-results/web-*.png`.
- Learning path: `../../work/tmp/bashkir-academy-{desktop,mobile}.png` относительно корня репозитория.

Видео записаны Playwright с реальными локальными материалами. Для гарантированной демонстрации TTS загружено подмножество настоящей колоды по source_ids аудиоманифеста. Результат урока вычислен приложением: пять ответов, четыре совпадения, 62 тренировочных XP. Серверные очки и успешный backend не имитировались. WebM содержит изображение экрана; звуковая дорожка Playwright не записывается. Воспроизведение подтверждено состоянием Audio/currentTime и браузерным TTS-тестом.

Скриншоты результата и профиля осмотрены визуально. Критических ошибок в выполненных сценариях не обнаружено; код продукта не изменялся. WebKit на Windows эмулирует мобильный браузер, но не заменяет проверку физического Safari/iOS. Ошибки загрузки ресурсов, специально вызванные тестами, сохраняются в журнале; неперехваченных JS-ошибок и прочих console error не было.

Установлен только недостающий WebKit; Chromium и FFmpeg уже находились в `../../work/browsers`. Перед прогоном задан PLAYWRIGHT_BROWSERS_PATH на этот каталог. Тяжёлые дополнительные зависимости не устанавливались.

Повтор: `python tests/browser_mobile_checkpoint.py` (после настройки PLAYWRIGHT_BROWSERS_PATH). Видео и скриншоты исключены из Git действующими правилами. Добавлен только тест мобильных сценариев и этот отчёт.
