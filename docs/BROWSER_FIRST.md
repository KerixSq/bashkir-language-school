# Браузер — основной канал обучения

## Почему меняем архитектуру

Прежде отдельная веб-игра хранила XP только в `localStorage`, а официальные ответы и рейтинги создавались через Telegram. Теперь на сайте есть самостоятельный серверный цикл подтверждения переводов. Старую тренировочную игру сохраняем для практики без входа, но её XP **не являются официальными очками**.

## Архитектура

```text
web/index.html — Supabase Auth (anonymous JWT)
        |  browser RPC only, no user_id from client
        v
PostgREST → SECURITY DEFINER web_* wrappers
        | auth.uid() ↔ users.auth_user_id
        v
get_next_fragment / submit_answer / skip_fragment
        |
        v
answers → reconcile_fragment → translations_export
        |
        +→ leaderboard_* / adventure_progress

Telegram bot → service_role → existing RPC (сохраняется)
```

## База и обновление

- В `users` добавлено поле `auth_user_id uuid unique`; `telegram_id` допускает NULL только для браузерных аккаунтов. Ограничение `users_identity_present` требует хотя бы один идентификатор.
- Миграция `sql/migrations/20261113_stage8_browser_first.sql` идемпотентна для существующей базы (выполнять **после** старых миграций).
- Публичные RPC `web_*` доступны только роли PostgreSQL `authenticated`, а не `anon`. Роль `authenticated` подтверждена Supabase Auth JWT, даже при анонимном входе.
- В SQL-функциях идентичность пользователя всегда определяется по `auth.uid()`, никогда не принимается произвольный `p_user_id` из браузера.
- Права на прямое чтение `users`/`answers` для `authenticated` не выдаются. Публичные рейтинги по-прежнему показывают только никнеймы.
- Очки и проверки антинакрутки остаются в старом `submit_answer` (минимальное время 2 секунды, дневной потолок, дубли, голосование).
- Код класса для учеников **необязателен** — самостоятельно занимающиеся ученики могут пройти задания, но не попадут в школьный рейтинг.

## Сеансы и ограничения

Анонимный Supabase Auth не запрашивает почту и телефон. Сессия остаётся в браузере. Если пользователь очистит хранилище, восстановить аккаунт без постоянного способа входа нельзя. Это подходит для хакатонного пилота, но для постоянной школы стоит добавить добровольную привязку постоянного входа.

Анонимные учётные записи не дают сильной защиты от создания множества аккаунтов. Лимиты ответов и голосов частично ограничивают накрутку, но её полностью не исключают.

`Tailwind Play CDN` официально предназначен для прототипирования, а не для публичного production-развёртывания. По текущему ТЗ оставили один HTML-файл и подключение через CDN. Для долгосрочного продукта можно позднее компилировать CSS без смены интерфейса.

## Как проверить вручную

1. Создай базу и импортируй реальные фразы БГПУ.
2. Примени stage8 и включи `enable_anonymous_sign_ins = true`.
3. В браузере подключи публичный ключ (не `service_role`).
4. Зарегистрируй никнейм, выбери пару, возьми задание.
5. Сразу нажми «Верно» — получи предупреждение «Подожди». Повтори через 2 секунды.
6. Проверь, что очки и ежедневная цель увеличились.
7. Получи следующее задание; исправь перевод, отправь исправление.
8. Открой рейтинги и проверь свой никнейм.
9. В новом браузерном профиле создай второго пользователя; удостоверься, что это другой аккаунт.
10. Заверши голосование третьим пользователем и проверь подтверждённую запись в `translations_export` и `adventure_progress`.
11. Убедись, что публичный ключ не даёт доступа к таблице `users`.
12. Обнови страницу: сессия и профиль должны сохраниться.

## Доступность и анимация

Две шрифтовые семьи: Nunito для заголовков и Manrope для интерфейса. Font Awesome 6 — только duotone/bold. GSAP/ScrollTrigger и Lenis подключены из CDN. При `prefers-reduced-motion` эффектная анимация выключается. Магнитное поведение кнопок включается только на устройствах с точным указателем.
