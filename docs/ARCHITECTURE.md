# Архитектура

Сайт, Telegram и REST используют одну локальную PostgreSQL. Это общая база ответов, а не единый аккаунт двух каналов.

```text
Nginx /web → локальные HTML/CSS/JS, колода и аудио
        ├→ Supabase Auth: anonymous JWT → users.auth_user_id
        └→ PostgREST → web_* RPC → get_next_fragment / submit_answer
Telegram aiogram → service_role → те же SQL-операции
answers → reconcile_fragment → translations_export / leaderboard_* / adventure_progress
```

Compose: db (PostgreSQL), rest (PostgREST), auth (GoTrue), app (Nginx). Необязательные bot и tor включаются профилем bot. Один polling-процесс на токен; scheduler напоминаний внутри этого процесса. Внешних очередей и облачных сервисов для основного локального запуска нет. Порт 54321 привязан к loopback.

## Идентичность и права

- `users.auth_user_id` уникален; `users_identity_present` требует хотя бы Auth или Telegram ID. Браузер получает идентичность из auth.uid(), не из произвольного user_id клиента.
- `web_*` доступны authenticated, включая анонимный Auth-сеанс, но не anon. Прямого публичного чтения users/answers нет. Публичные представления не возвращают ID школьников.
- service_role используется только доверенным ботом/CLI; браузеру передаётся только публичный ключ. Учительский и экспертный доступ защищены кодами.
- Ученик может учиться без класса, преподавателю нужен класс. Независимые web/Telegram-профили не объединяются и не суммируются.
- Анонимный Auth-сеанс хранится в браузере; после очистки хранилища без постоянной привязки восстановление не гарантируется. Массовое создание аккаунтов/сговор полностью не исключены.

## Веб-интерфейс

`web/index.html` содержит приложение и бизнес-операции без UI-фреймворка. `web/assets/navigation.js` отвечает только за навигацию; `visual-polish.css` — за текущую геометрию и визуальные токены. Supabase JS, SVG и обязательные данные поставляются локально, CDN-шрифты необязательны. Библиотека клиента пересоздаётся при смене URL/публичного ключа, прежнее автообновление сессии останавливается.

Тренажёр хранит XP, стадии и награды в localStorage. Серверная проверка записывает ответы PostgreSQL; только эти ответы влияют на консенсус, серверный рейтинг и библиотеку. Значения без API показываются как неизвестные, а не вымышленные лидеры.

Навигация использует упорядоченные видимые границы, один passive scroll-listener и один requestAnimationFrame. Гистерезис 12 px устраняет колебания у границы. Выбор меню удерживается при программном переходе; wheel/touch/клавиатура/ручное перемещение отменяют удержание. Скрытые tabpanel не участвуют в выборе, состояние вкладки берётся из openTab. ResizeObserver пересчитывает границы после изменения высоты. Контекст перезаписывается только при изменении раздела или отображаемых данных. На обычном desktop sidebar неподвижен без отдельной прокрутки; низкий экран имеет доступный fallback.

## Данные и эксплуатация

Формулы очков, веса, антидубли и SQL-консенсус остаются в sql/logic.sql и миграциях. Проверка трёх участников не заменяет экспертизу языка. Контракт экспорта содержит ровно семь полей; оригинальные таймкоды находятся в source. Подробности: [API](../API.md), [спецификация](../SPEC.md), [игровые правила](GAMEPLAY.md).

Чистая установка использует schema → seed → logic один раз. Существующая БД обновляется только выбранным суффиксом миграций после backup; обе stage11 имеют разное назначение. [Windows setup](WINDOWS_SETUP.md). Нельзя удалять volume или менять сохранённые пароли/JWT вслепую. Для публичного размещения нужны отдельные HTTPS и защита; текущий локальный стек не публикуют напрямую.

## Проверка

Unit и контракт проверяют структуру/чистую логику; PostgreSQL integration создаёт disposable БД; Docker integration — отдельный Compose-проект. Aiogram тестируется реальными обработчиками с подменённым Telegram transport. Playwright проверяет локальные файлы и настоящий QA REST; это не Live Telegram E2E. [Фактические результаты и ограничения](QA.md).
