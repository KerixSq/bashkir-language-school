# Основная защита: три минуты

Подготовка до показа: [Windows setup](WINDOWS_SETUP.md), корпус БГПУ на отдельной демонстрационной базе, все миграции до stage14 (обе stage11). Проверить readiness/RLS. Подготовить настоящего тестового Telegram-ученика и два независимых профиля браузера; им нужны разные серверные пользователи. Убедиться заранее, что выдан один и тот же фрагмент и нет старых ответов этих участников. В рабочей базе ничего не очищать и не подгонять статусы/голоса SQL-командами. Секретные панели закрыть.

| Время | Действие и проверяемый результат |
|---|---|
| 0:00–0:20 | Карта и Акбузат. «Пять упражнений для тренировки, отдельно — совместная проверка переводов». |
| 0:20–0:40 | Начать урок, выполнить одно задание на фразе БГПУ. При наличии записи — TTS; назвать её синтезированной. Локальные XP не являются голосом. |
| 0:40–1:10 | Telegram `/task`: показать реальную фразу и источник, подтвердить верный вариант или ввести исправление. Показать обратную связь и личный вклад. Ученику не нужен класс. |
| 1:10–1:50 | Два независимых веб-профиля: серверная проверка того же фрагмента, реальные ответы. При трёх согласованных вариантах SQL устанавливает confirmed. Не обещать консенсус, если ответы различаются. |
| 1:50–2:20 | На сайте открыть подтверждённый перевод и обновить общую библиотеку. Показать итог, источник и число голосов. |
| 2:20–2:40 | JSON/CSV текущей базы и публичный REST `translations_export`. Ровно семь полей, таймкоды — внутри source. |
| 2:40–3:00 | Кратко: эксперт видит варианты/голоса/сходство и сам принимает решение; исходное аудио играет диапазон. Если показан тестовый тон — назвать технической фикстурой. Завершить ссылкой на зелёный RC CI. |

Для предсказуемого показа используйте заранее проверенную выдачу в демонстрационной базе, не успешные заглушки API. Если совпадения выдачи нет, покажите существующий настоящий консенсус с реальными ответами и честно объясните это. Три голоса сообщества — не экспертиза носителей. Веб и Telegram используют общую базу, но независимые аккаунты.

Меню, `/join`, отчёт преподавателя и `/remind on/off` — запас для вопросов жюри. Не расходовать на них основной тайминг. Доставка напоминания вне часового окна не имитируется. [Резервный показ](DEMO.md).


## Резервный показ

| Отказ | Действие |
|---|---|
| Telegram недоступен | Продолжить серверную проверку в трёх независимых браузерных профилях. Назвать канал Telegram недоступным сейчас. Показать результат aiogram integration с подменённым transport как автоматический тест, не Live E2E. |
| Tor недоступен | Если Telegram доступен напрямую, осознанно выбрать direct по WINDOWS_SETUP. Остановить прежний экземпляр, не запускать второй polling. Если прямого доступа нет — браузерный сценарий. |
| Нет интернета | Уже собранный Docker, импортированный корпус, локальный JS и WAV работают без CDN. Не обещать Telegram и скачивание корпуса. Образы/данные подготовить заранее. |
| Нет аудиозаписи/звука | Показать честное состояние недоступности и продолжить текстовое задание. Не заменять башкирский русским браузерным голосом. TTS — только 40 записей; оригинальный тестовый тон не речь. |
| Нет задания или голоса разошлись | Показать реальный confirmed из сохранённой базы, затем экспертную очередь. Не менять статусы вручную ради результата и не выдавать учебные XP за консенсус. |
| Docker не стартовал | Показать заранее сохранённую запись и успешный CI с точным SHA. Чётко обозначить запись и причину отсутствия живого API. Нельзя рисовать успешные серверные ответы. |

Заранее сохранить `test-results/checkpoint/chromium-mobile.webm`, `webkit-mobile.webm`, скриншоты `test-results/visual/` и ссылку на Actions. Эти видео показывают локальный тренажёр и аудио; они **не доказывают живой Telegram или серверный консенсус**. Артефакт CI interface-screenshots содержит свидетельства; original-audio-evidence — техническое аудио. Для показа Live Telegram нужна отдельная реальная запись, полученная с разрешения тестового участника; в RC-аудите её не создавали.

Не открывайте `.env`, токены, пользовательские идентификаторы и коды доступа на трансляции. План восстановления не включает очистку базы или удаление volume.


## Вопросы жюри


**1. Как учитываются синонимы?** Нормализация объединяет некоторые записи, `synonym_map` хранит вручную заданные эквивалентности. Семантической модели нет; похожее написание лишь помечается для эксперта.

**2. Кто гарантирует верность перевода?** На этом этапе никто: консенсус пользователей не равен филологической экспертизе. Эксперт может подтвердить итоговый вариант, но УФИЦ РАН к проекту не подключён.

**3. Можно ли накрутить баллы?** Есть минимальное время задания, интервал ответов, дневной потолок, один ответ на перевод и вес надёжности. Сговор нескольких аккаунтов всё ещё возможен.

**4. Почему два интерфейса?** Telegram удобен для коротких заданий; сайт — также самостоятельная проверка переводов, отчёты, экспорт и экспертная очередь.

**5. Что храните о школьниках?** В боте хранится Telegram ID и служебные настройки; публичный рейтинг содержит только никнейм. `/delete_me` обезличивает профиль, сохраняя анонимные голоса.

**6. Как подключить новую школу?** Класс можно создать подтверждённому преподавателю по приглашению через `/newclass` или серверным скриптом. Полноценной административной панели школ пока нет.

**7. Как соблюдается авторское право?** Импорт записывает источник, лицензию и URL. Команда должна проверить разрешение и условия атрибуции CC BY 4.0; система не делает это автоматически.

**8. Почему веса не равны?** Участник, ранее распознавший подставные ошибки, получает немного больший вес; подтвердивший ошибки — меньший. Ограничение 0.5–1.5 не заменяет проверку реальными экспертами.

**9. Где аудио?** В схеме есть тип источника и время начала/конца; воспроизведения и TTS нет.

**10. Может ли другая школа подключиться по API?** Есть публичные представления и отдельный API по партнёрскому ключу для чтения и внешних предложений. Внешние предложения хранятся отдельно от голосов учеников, поэтому сами по себе не меняют консенсус.



До показа: проверить backup/миграции, readiness/RLS, реальный консенсус и экспорт; не показывать временные записи smoke (он очищает их). Убедиться в единственном polling. Произношение/переводы не проверены носителем; независимые профили не объединены. Ручной live-чек-лист — [WINDOWS_SETUP](WINDOWS_SETUP.md); фактический статус — [QA](QA.md).
