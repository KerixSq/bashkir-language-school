Источник — Bashkorttele / БГПУ, пять зафиксированных JSONL, CC BY 4.0. Правообладатель: ФГБОУ ВО «БГПУ им. М. Акмуллы»; издатель: АНО «Фонд сохранения и развития башкирского языка». Атрибуция, ссылка на лицензию и указание изменений обязательны. Лицензия текста не распространяется на иллюстрации/типографику печатных изданий. Ревизия/хеши: [CORPUS_PROVENANCE.json](CORPUS_PROVENANCE.json), LICENSE/NOTICE: web/assets/corpus/. Загрузчик проверяет хеши и не перезаписывает изменённые локальные файлы. Пары импортёра: ba-ru и ba-kk.

Дедупликация выполняется по нормализованному text_ba, исходные ID сохраняются в закрытой phrasebook_rows с префиксом файла. Частотный выбор русского варианта и подставные переводы — эвристики, не доказательство языковой правильности. `--review-out` создаёт CSV для проверки. [Инструкция импорта текста](../scripts/IMPORT_GUIDE.md).

В сухом прогоне исходного архива ревизии fa499b98b24a97a696b10ce4265af129a2bf526c было 9857 строк, 9852 подходящих, 3834 уникальных фрагмента, 5208 языковых связей; 1206 групп с разными русскими вариантами и 13 с различающейся пунктуацией. При bad-share 0.2 — 1042 подстановки. Это исторические характеристики корпуса, не результаты проверки носителями и не счётчики рабочей базы.

Учебная колода содержит 700 записей (350 на пару), уникальные ID и непустые тексты; UTF-8 без U+FFFD. Длинные списки требуют ручной проверки: ba-ru:00b1f66a-0d99-592a-a0c6-27a52c115b20 (ремонт обуви), обе пары a2472cca-33d8-5cec-8b4b-6e3381bcdbc3 (зодиак), обе пары c3894e3b-d80d-5cd6-a55e-f09397eb5a4d (родственные термины). Это сомнения для носителя, не автоматически установленные ошибки. Переводы при консолидации не менялись.

## Работа с переводами из CSV

`export_for_translation.py` выдаёт fragment_id,text_ba,lang_pair,chapter,position. Подготовленный перевод для `import_translations.py` должен содержать ровно четыре колонки: `fragment_id,lang_pair,auto_translation,bad_translation`. ID и языковую пару сохраняют побуквенно; одна исходная строка — одна итоговая. Значения с запятыми/кавычками экранируют по CSV; кавычки внутри удваивают. Никаких Markdown-ограждений, пояснений и дополнительных колонок в CSV. Пустой bad_translation допустим; непустой должен отличаться от основного и проходить ручную проверку. Не придумывайте переводы и подставные ошибки автоматически: неоднозначные случаи оставляйте для эксперта. Для использования проверьте выборку основных и ошибочных вариантов с носителем. Подтверждение сообщества не равнозначно такой проверке.

## Башкирская озвучка · Silero bak_aigul

## Что доступно

В `web/assets/audio/` включены **40 синтезированных WAV** (24 kHz, mono PCM16, около 3,9 MB) и `manifest.json`. Они созданы только из включённой колоды БГПУ, без новых предложений и изменения переводов. В manifest указаны исходные ID, нормализованный текст, голос, версия модели и SHA-256 каждого файла. Одинаковые нормализованные фразы обеих языковых пар используют один файл.

Кнопка «Слушать» находится рядом с башкирской фразой в тренировке и серверной проверке. Воспроизведение начинается только по нажатию; повторное нажатие, смена задания, выход и уход со страницы останавливают звук. Есть состояния загрузки, остановки, отсутствия озвучки и ошибки с повторной попыткой. Источник, название модели и предупреждение об оценке носителем находятся в раскрывающемся блоке «Источник и озвучка»; основной экран сохраняет подпись «Синтезированная речь». Enter/Space на динамике не отправляют выбранный ответ. Файлы раздаются существующим Nginx или обычным статическим HTTP-сервером. SQL, Docker, начисление XP и серверные очки не изменены. На клиентские или внешние TTS-сервисы фразы не отправляются.

**Это синтезированная речь. Произношение не проверено носителем.** До использования озвучки в учебном пилоте необходима оценка носителем башкирского языка, включая специфические буквы и ударения. Техническое воспроизведение не подтверждает языковую правильность. Аудио покрывает 40 из 627 уникальных допустимых для генератора фраз; остальные задания работают в текстовом виде. Корпус также содержит варианты через `/`: генератор их пропускает без изменения текста. Русский браузерный голос не используется как башкирский; SpeechSynthesis не вызывается.

## Генерация на Windows

Готовые WAV уже в Git: для запуска сайта PyTorch не нужен. Для генерации создайте отдельное необязательное окружение, не используемое контейнерами:

```powershell
python -m venv .venv-tts
.\.venv-tts\Scripts\python.exe -m pip install -r requirements-tts.txt
.\.venv-tts\Scripts\python.exe scripts/generate_tts.py --limit 40 --dry-run
.\.venv-tts\Scripts\python.exe scripts/generate_tts.py --limit 40 --download-model
```

`--download-model` скачивает только официальный URL в `.cache/tts/` (не входит в Git). Без этого флага передайте уже проверенный файл через `--model-file C:\path\v5_cis_base_nostress.pt`. `--dry-run` не требует модели, сети и PyTorch, ничего не записывает. Пример расширения на всю колоду:

```powershell
.\.venv-tts\Scripts\python.exe scripts/generate_tts.py --voice bak_aigul --model-file .cache/tts/v5_cis_base_nostress.pt
```

Без `--limit` обрабатываются все допустимые уникальные фразы. `--output-dir` задаёт папку результата (по умолчанию `web/assets/audio`); для сайта содержимое должно оказаться именно там. Существующие WAV проверяются и пропускаются; хеш имени включает текст, голос, модель и контрольную сумму модели. Manifest отражает выбранный текущей командой набор. Повторная команда с теми же аргументами не пересинтезирует файлы. Повреждённый файл вызывает ошибку, а не считается успешным кешем. Зависимости TTS не добавлены в зависимости приложения.

## Исходное аудио с готовыми таймкодами — ТЗ 4.2

Импортёр принимает PCM WAV или MP3 и UTF-8 JSON/CSV с полями `time_start`, `time_end`, `text_ba`, `translation`, `lang_pair`. Он не распознаёт речь и не генерирует транскрипты/переводы. Для настоящего материала нужны разрешение на публикацию, название источника, лицензия и подготовленная разметка. Синтетическая TTS остаётся отдельным проигрывателем.

JSON — массив объектов; CSV — заголовок из тех же пяти полей. Технический пример структуры (не башкирская фраза):

```json
[{"time_start":0.2,"time_end":0.7,"text_ba":"TECHNICAL FIXTURE - NOT BASHKIR","translation":"Техническая фикстура, не речь.","lang_pair":"ba-ru"}]
```

Допустимы ba-ru/ba-kk, от 1 до 1000 строк, аннотация до 2 MB и RPC-пакет до 900 kB (при превышении нужно разделить разметку), аудио до 256 MiB/8 часов. Все интервалы должны быть конечными числами, `0 <= start < end <= длительность`. Текст и перевод обязательны; неверные поля и повтор интервала одной языковой пары отклоняются. Перекрытие интервалов разных сегментов допускается (например, диалог); импортёр не считает его ошибкой языка. WAV проверяется на полноту PCM-кадров. Для MP3 требуется **уже установленный ffprobe**; если его нет, импортёр честно отказывает и предлагает PCM WAV. Тяжёлые модели и новые службы не нужны.

## Импорт на Windows

Сначала проверка без записи (пути ниже заменяются на настоящий лицензированный материал):

```powershell
python scripts/import_audio.py --audio C:\Materials\original.wav --segments C:\Materials\segments.json --title "Название источника" --license "Лицензия правообладателя" --dry-run
python scripts/import_audio.py --audio C:\Materials\original.wav --segments C:\Materials\segments.json --title "Название источника" --license "Лицензия правообладателя" --env-file .env.docker
docker compose --env-file .env.docker up -d --build app
```

Env-файл выбирается явно; URL и серверный ключ не наследуются от другого окружения. Для `.env.docker` берутся loopback URL и SERVICE_ROLE_KEY. Сам `.env.docker` импортёр не изменяет. MP3 используется теми же командами с файлом `.mp3` и существующим ffprobe в PATH. Для CSV укажите `.csv` вместо `.json`.

Опубликованная копия получает права 0644, чтобы её мог читать рабочий процесс Nginx; права исходного файла не меняются. Аудио копируется в `web/assets/original-audio/<sha256>.wav|mp3`, путь хранится в sources.url. Каталог исключён из Git, но включается в локальную сборку app. Сохраняйте его вместе с резервной копией базы. Удаление Docker volumes или сброс БД не требуются. Без пересборки app новый файл может возвращать 404; текстовое задание остаётся доступным.

Повтор идентичного материала/разметки/метаданных даёт те же UUID, не создаёт дубликаты и не сбрасывает ответы/подтверждённые переводы. Одинаковый интервал и башкирский текст для двух языков используют один fragment и разные pairs. Изменённая разметка или атрибуция образует отдельный импорт, сохраняя старую историю. Существующий файл с неверным хешем не перезаписывается. Все строки БД сохраняются одной транзакцией через import_audio_fragments; при ошибке БД не остаётся частичного источника. Файл копируется до транзакции: при сетевом отказе может остаться неиспользуемый локальный asset, повтор импорта безопасен; автоматического удаления файлов нет.

## Воспроизведение и API

Задание из `web_next_fragment`/`get_next_fragment` дополнительно содержит `source_kind`, `source_url`, `source_license`, а также прежние time_start/time_end. Для локального безопасного пути аудио сайт показывает «Слушать оригинал», источник, лицензию и диапазон. Повторное нажатие останавливает, новое начинает диапазон сначала; конец диапазона, ответ, пропуск и смена задания останавливают проигрывание. Ошибка загрузки сообщает о проблеме и позволяет повторить, не блокируя текстовую проверку. При сетевом отказе отправки ответа проигрывание приостанавливается, но источник и незавершённое задание сохраняются. URL сторонних сайтов, javascript и произвольные пути не принимаются проигрывателем. Сам RPC задания возвращает только безопасный локальный путь: старые приватные/внешние URL источников не раскрываются. После ошибки повтор создаёт отдельную попытку загрузки, чтобы не использовать закешированную ошибку медиадекодера.

`import_audio_fragments(p_source jsonb,p_segments jsonb)` доступен только service_role. Публичным ролям его исполнение запрещено; произвольной загрузки файлов из браузера нет. Семь полей translations_export сохранены: название, позиция и таймкоды остаются внутри source. После трёх согласованных голосов итог экспортируется обычным SQL-консенсусом.

Применение stage13 и сохранение оригинальных аудиофайлов вместе с backup — [WINDOWS_SETUP](WINDOWS_SETUP.md). Технические тестовые тоны не являются подлинным башкирским аудиокорпусом. Текущие результаты проверки WAV/manifest, браузеров и хешей — [QA](QA.md).
