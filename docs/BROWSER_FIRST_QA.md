# Браузерная версия — результаты проверок

Дата: 13 ноября 2026. Исходник: последняя игровая сборка проекта.

## Проверено в рабочем контейнере

- `python -m unittest discover -s tests -q`: 86 тестов, OK.
- `python -m compileall -q bot scripts tests`: без ошибок.
- `python scripts/check_contract.py`: PASS статической проверки.
- Синтаксис каждого встроенного JS-блока `web/index.html`: PASS в Node.js.
- Chromium через Playwright `page.set_content` (навигация на localhost была заблокирована окружением): 1440px и 390px, ошибок JS нет, горизонтального переполнения нет.
- В браузерном тесте с имитацией Supabase Auth и RPC: регистрация по никнейму, получение задания, отправка подтверждения, обновление серверных очков на странице — успешно.
- Тест имитирует API и НЕ доказывает реальную работу PostgreSQL, выдачу JWT, права RLS и сетевую доступность локального API.

## Что не проверено

- Исполнение `sql/migrations/20261113_stage8_browser_first.sql` на реальном PostgreSQL, включая её повторный запуск.
- Включение анонимной авторизации в Supabase CLI Windows.
- Настоящая работа auth JWT и вызовов SECURITY DEFINER через PostgREST.
- Реальные ответы трёх разных учеников, согласование, рейтинги и начисление очков.
- Работа CDN Tailwind, Google Fonts, Font Awesome, GSAP, Lenis в среде с интернетом (в browser smoke CDN-запросы были намеренно заблокированы).
- Проверка PowerShell-скрипта в Windows (PowerShell в этом контейнере отсутствует).
- Ruff в этом контейнере отсутствует.

## Приоритеты реальной проверки

1. Подними локальный Supabase и включи Anonymous Sign-Ins.
2. Примени stage8 на копии существующей базы; проверь rollback при ошибках и повторное применение.
3. В браузере войди по никнейму; проверь, что профиль сохранился после обновления.
4. Получи фразу, проверь слишком быстрый ответ и повтори через 2 секунды.
5. Ответь на 5 фраз, посмотри цели и рейтинг.
6. Используй ещё 2 разных анонимных браузерных сеанса, достигни консенсуса.
7. Проверь рост `adventure_progress` и появление строки в `translations_export`.
8. Выполни `scripts/check_rls.py`; убедись, что `anon` и `authenticated` не могут напрямую читать `users`/`answers`.
9. Проверь, что мобильное устройство подключается к настоящему API только по безопасному доступному адресу, не по `127.0.0.1` ноутбука.
