# Финальная автоматическая проверка Telegram-бота

Исторический снимок раннего QA-этапа. Текущая реализация, напоминания и результаты общего аудита: [FINAL_HACKATHON_QA.md](FINAL_HACKATHON_QA.md).

Дата: 2026-11-14. Изменён только `tests/bot_integration.py`; обработчики, SQL и Docker не менялись.

## Способ проверки

Используются реальные aiogram Router/Dispatcher и `Dispatcher.feed_update`, настоящие PostgreSQL и PostgREST. Telegram Update создаётся тестом; Bot API заменён `TelegramStub`. Сеть Telegram, polling, webhook и реальные аккаунты не используются. Это интеграционный тест обработчиков и базы, **не Live E2E**.

Локальный прогон выполнен на существующей отдельной QA-базе `bsk_live_telegram` (PostgreSQL 17, localhost:55445, PostgREST через localhost:55447). В ней создаются уникальные технические пользователи, языковая пара, школа, класс, источник и два задания. Тексты явно технические и не выдаются за башкирский корпус. Обработчики работают с ними через обычные RPC. `finally` удаляет только UUID/код собственных фикстур; другие записи и конфигурация не изменяются. Запущенные для прогона QA-службы затем остановлены, файлы базы сохранены.

## Границы покрытия

Проверена первая награда; пороги остальных достижений и многодневные серии этим прогоном не подтверждены. Для `/newclass` проверены права и валидация, но успешное создание по действующему приглашению не проверялось: тест не меняет глобальный teacher_invite_code. Не проверены гонки параллельных callback, реальная транспортная ошибка Bot API и физический рестарт PostgreSQL в середине сценария. Перезапуск Python-процесса подтверждает сохранность FSM/ответов/баллов вне памяти Dispatcher; это не заменяет тест рестарта БД. Существующий `tests/docker_integration.py` уже включает тест сохранности стека и вызывает расширенный bot integration; в этом прогоне Docker не запускался.

## Повторный запуск

После настройки **отдельного тестового** SUPABASE_URL/SUPABASE_SECRET_KEY до импорта `bot.db`:

```powershell
python tests/bot_integration.py
```

Для существующего изолированного Compose-теста:

```powershell
python tests/docker_integration.py
```

Второй тест создаёт собственный проект Compose и сохраняет его volume. Отдельный live smoke остаётся самостоятельной ручной проверкой; его результаты не подменяются этим тестом.
