# Telegram: самостоятельное обучение и общая библиотека

В настройках также доступны добровольные напоминания `/remind on/off`; по умолчанию выключены. Порядок обновления до stage14 — [Windows setup](WINDOWS_SETUP.md).

`/start` → никнейм → ученик → «Учиться самостоятельно» → языковая пара. Код класса не нужен. `/join` или «Настройки → Вступить в класс» принимает ученический код, сохраняя тот же UUID, ответы и серверные баллы. Преподавателю по-прежнему нужен отдельный секретный код класса.

Главное меню: задание, прогресс, вклад, рейтинг, настройки и сайт. Преподавателю доступны класс и CSV-отчёт. После ответа, пропуска и отмены есть следующий шаг. Во время исправления смена пары/класса блокируется; `/cancel` отменяет незавершённое действие. Старые команды сохранены; добавлена `/join`.

«Вклад в библиотеку» использует только ответы текущего Telegram-пользователя, user_stats и публичный adventure_progress. Счётчики статусов вычисляются сервером с точным count, история ограничена последними 20 проверками. Подтверждение сообществом не называется экспертизой. Тренировочные XP сайта не добавляются к этим очкам.

## Запуск Windows

Основной сайт, без Telegram-токена и Tor:

```powershell
docker compose --env-file .env.docker up -d --build --wait
```

Бот через Tor (токен уже настроен в приватном окружении):

```powershell
docker compose --env-file .env.docker --profile bot up -d --build tor bot
docker compose --env-file .env.docker logs --tail 30 tor bot
```

Tor остаётся прокси по умолчанию. Бот не ждёт внешнего healthcheck Tor: временная недоступность приводит к повторному запуску бота по restart policy, а не к переходу на прямую сеть. Healthcheck Tor проверяет внешний Tor exit с ограничением времени и допускает пробелы в JSON. Реальная доступность Tor зависит от сети.

Явный прямой запуск после запуска основного сайта, без запуска Tor:

```powershell
$env:BOT_PROXY_URL = 'direct'
docker compose --env-file .env.docker --profile bot up -d --build --no-deps bot
Remove-Item Env:BOT_PROXY_URL
```

Для своего прокси укажите socks5/socks4/http URL с портом в приватном окружении. При ошибке настроенного прокси прямого fallback нет. Ошибки запуска логируют только тип исключения, без URL с паролем или токена. Локальный Python без BOT_PROXY_URL использует direct; Compose без переменной — Tor. Не меняйте пароли и JWT существующего volume.

## Публичные переходы

Необязательный BOT_USERNAME (без токена) передаётся приложению через BASHKIR_PUBLIC_CONFIG.bot_username. Например, установите `$env:BOT_USERNAME='your_school_bot'` перед пересозданием app. Если username отсутствует/невалиден, ссылка не публикуется. Токен остаётся только в bot.

PUBLIC_WEB_URL — необязательный публичный HTTPS-адрес корня веб-приложения, например `https://school.example/web/`. Кнопки Telegram ведут на сайт, игру и библиотеку. Для локального адреса вместо публичной кнопки показывается объяснение, что сайт доступен на ноутбуке организатора. DNS и доступность настроенного домена автоматически не гарантируются.

Веб и Telegram используют общие SQL, answers, fragment_pairs, рейтинги, translations_export и adventure_progress. Аккаунты пока независимы; их автоматическое объединение не реализовано. Переход по ссылке не переносит сессию и не связывает аккаунты.

## Добровольная ежедневная практика

Напоминания изначально выключены. После регистрации в Telegram можно использовать `/remind on`, `/remind off` или «Меню → Настройки → Напоминания». `/remind` без аргумента показывает состояние. Отказ от уведомлений не удаляет прогресс, ответы или незавершённое задание. Преподавателю нужна завершённая регистрация с классом, ученику класс не обязателен.

При включении пользователь явно соглашается на сообщения. В уведомлении есть «Задание дня» (реальный существующий обработчик) и переход к настройкам. Тренировочные XP браузерной игры не засчитываются как серверная дневная цель.

## Планировщик и гарантии

- Работает в том же процессе aiogram и использует тот же Bot/proxy; второго polling, Redis/Celery и внешнего cron нет. В LIVE_TELEGRAM_TEST_ONLY планировщик отключён.
- Раз в 60 секунд PostgreSQL выбирает до 20 согласившихся зарегистрированных пользователей. Время берётся с сервера БД, часовой пояс — Asia/Yekaterinburg (Уфа). Существующий config.reminder_hour по умолчанию 18: окно 18:00–18:59. Если бот был выключен всё окно, ночной рассылки задним числом нет.
- Не выбираются удалённые профили, web-only аккаунты без положительного Telegram ID, завершившие серверную дневную цель и пользователи без доступных заданий. Уведомления не меняют баллы, рейтинг или статистику ответов.
- FOR UPDATE SKIP LOCKED и атомарное обновление существующего last_reminder_date исключают повторное резервирование дня параллельными процессами и после рестарта. `/off` → `/on` не сбрасывает дату.
- Дата фиксируется **до** отправки. Это резервирование одной попытки, не доказательство доставки. Сбой/рестарт после резервирования может оставить пользователя без напоминания на этот день. После тайм-аута повторной отправки в тот же день нет: запрос уже мог быть доставлен.
- Непосредственно перед отправкой повторно проверяются цель, согласие, Telegram ID и удаление. Уже начатый HTTP-запрос невозможно атомарно отменить вместе с `/off`/удалением/новым ответом; короткая гонка с одновременным изменением неизбежна. Строгая exactly-once доставка не заявляется.
- TelegramForbiddenError (блокировка бота) выключает reminders_enabled. Ошибки логируются только по типу, без токенов, адресов прокси и идентификаторов получателей. Последующая разблокировка требует нового `/remind on`.

Новый claim_daily_reminders(p_now timestamptz default now(),p_limit integer default 20) доступен только service_role. Инъекция часов нужна для тестов; браузер не может вызвать этот RPC или получить список получателей. Публичные права и семь полей translations_export не менялись. Существующие согласия/даты миграция сохраняет; default false применяется к новым профилям.

Миграции, включая обе stage11 и stage14, Tor/direct и один polling: [WINDOWS_SETUP](WINDOWS_SETUP.md). Неизвестные slash-команды не записываются как перевод и не меняют FSM. Автоматические Dispatcher.feed_update/PG проверки с подменённым transport — не Live E2E. Реальный ручной протокол с изоляцией аккаунта и env: [TELEGRAM_LIVE_TEST](TELEGRAM_LIVE_TEST.md).
