# Исходное аудио с готовыми таймкодами — ТЗ 4.2

Импортёр принимает PCM WAV или MP3 и UTF-8 JSON/CSV с полями `time_start`, `time_end`, `text_ba`, `translation`, `lang_pair`. Он не распознаёт речь и не генерирует транскрипты/переводы. Для настоящего материала нужны разрешение на публикацию, название источника, лицензия и подготовленная разметка. Синтетическая TTS остаётся отдельным проигрывателем.

JSON — массив объектов; CSV — заголовок из тех же пяти полей. Технический пример структуры (не башкирская фраза):

```json
[{"time_start":0.2,"time_end":0.7,"text_ba":"TECHNICAL FIXTURE - NOT BASHKIR","translation":"Техническая фикстура, не речь.","lang_pair":"ba-ru"}]
```

Допустимы ba-ru/ba-kk, от 1 до 1000 строк, аннотация до 2 MB и RPC-пакет до 900 kB (при превышении нужно разделить разметку), аудио до 256 MiB/8 часов. Все интервалы должны быть конечными числами, `0 <= start < end <= длительность`. Текст и перевод обязательны; неверные поля и повтор интервала одной языковой пары отклоняются. Перекрытие интервалов разных сегментов допускается (например, диалог); импортёр не считает его ошибкой языка. WAV проверяется на полноту PCM-кадров. Для MP3 требуется **уже установленный ffprobe**; если его нет, импортёр честно отказывает и предлагает PCM WAV. Тяжёлые модели и новые службы не нужны.

## Миграция существующей базы

После обычной резервной копии и прежних миграций P0/stage12:

```powershell
docker compose --env-file .env.docker cp sql/migrations/20261114_stage13_original_audio.sql db:/tmp/stage13.sql
docker compose --env-file .env.docker exec -T db psql -U postgres -d bashkir -v ON_ERROR_STOP=1 -f /tmp/stage13.sql
```

Stage13 транзакционная и повторяемая. Она добавляет только серверный RPC импорта и дополнительные поля задания; существующие таблицы, ответы, права публичных ролей и формулы баллов сохраняются. На пустой базе всё включено в logic.sql. Полные schema/seed/logic поверх существующего volume не запускаются.

## Импорт на Windows

Сначала проверка без записи (пути ниже заменяются на настоящий лицензированный материал):

```powershell
python scripts/import_audio.py --audio C:\Materials\original.wav --segments C:\Materials\segments.json --title "Название источника" --license "Лицензия правообладателя" --dry-run
python scripts/import_audio.py --audio C:\Materials\original.wav --segments C:\Materials\segments.json --title "Название источника" --license "Лицензия правообладателя" --env-file .env.docker
docker compose --env-file .env.docker up -d --build app
```

Env-файл выбирается явно; URL и серверный ключ не наследуются от другого окружения. Для `.env.docker` берутся loopback URL и SERVICE_ROLE_KEY. Сам `.env.docker` импортёр не изменяет. MP3 используется теми же командами с файлом `.mp3` и существующим ffprobe в PATH. Для CSV укажите `.csv` вместо `.json`.

Аудио копируется в `web/assets/original-audio/<sha256>.wav|mp3`, путь хранится в sources.url. Каталог исключён из Git, но включается в локальную сборку app. Сохраняйте его вместе с резервной копией базы. Удаление Docker volumes или сброс БД не требуются. Без пересборки app новый файл может возвращать 404; текстовое задание остаётся доступным.

Повтор идентичного материала/разметки/метаданных даёт те же UUID, не создаёт дубликаты и не сбрасывает ответы/подтверждённые переводы. Одинаковый интервал и башкирский текст для двух языков используют один fragment и разные pairs. Изменённая разметка или атрибуция образует отдельный импорт, сохраняя старую историю. Существующий файл с неверным хешем не перезаписывается. Все строки БД сохраняются одной транзакцией через import_audio_fragments; при ошибке БД не остаётся частичного источника. Файл копируется до транзакции: при сетевом отказе может остаться неиспользуемый локальный asset, повтор импорта безопасен; автоматического удаления файлов нет.

## Воспроизведение и API

Задание из `web_next_fragment`/`get_next_fragment` дополнительно содержит `source_kind`, `source_url`, `source_license`, а также прежние time_start/time_end. Для локального безопасного пути аудио сайт показывает «Слушать оригинал», источник, лицензию и диапазон. Повторное нажатие останавливает, новое начинает диапазон сначала; конец диапазона, ответ, пропуск и смена задания останавливают проигрывание. Ошибка загрузки сообщает о проблеме и позволяет повторить, не блокируя текстовую проверку. URL сторонних сайтов, javascript и произвольные пути не принимаются проигрывателем.

`import_audio_fragments(p_source jsonb,p_segments jsonb)` доступен только service_role. Публичным ролям его исполнение запрещено; произвольной загрузки файлов из браузера нет. Семь полей translations_export сохранены: название, позиция и таймкоды остаются внутри source. После трёх согласованных голосов итог экспортируется обычным SQL-консенсусом.

## Подтверждённые проверки

- 143 unit-тест, compileall, контракт и Ruff — локально PASS.
- 11 PostgreSQL integration-тестов — PASS: повтор stage13, атомарный откат, запрет anon, повтор импорта, задания и консенсус/экспорт с таймкодами, сохранность экспертного этапа и P0.
- Chromium и WebKit — PASS для реальных PCM WAV и MP3 через HTTP, клавиатуры, остановки по диапазону, смены задания и запрета внешнего URL. MP3-прогон использует имеющиеся FFmpeg/ffprobe; при их отсутствии в другом окружении явно SKIP.
- Прежние browser checks, visual, TTS и mobile checkpoint — PASS локально.
- Изолированный Docker E2E дополнен полным циклом: импорт → публикация реального файла в Nginx → Auth-профиль → диапазон → ошибка/повтор → ответ браузером → PostgreSQL/таймкоды. Локально Docker SKIP (daemon недоступен), результат Actions проверяется после публикации коммита. Артефакт CI: original-audio-evidence.

Демо-фикстура в тестах — тихий синусоидальный тон с явной маркировкой TECHNICAL/NOT BASHKIR, не человеческая речь и не башкирский корпус. Подлинного аудиокорпуса с подтверждённым транскриптом в этом этапе не добавлено. Проверка языка носителем и качества реального транскрипта остаётся ручной.
